**Systematic query freeze does not constitute systematic-search execution.** Query definitions and versioned corrections are preserved independently of whether a Query ID is selected by the Protocol v1.1 tiered execution policy.

The protocol is the methodological authority. The search log supplies calibrated terminology and status; the systematic-search design supplies the conceptual branch structure; database-validation supplies the operational capabilities and limitations. Query terminology is retrieval terminology only. It is not a finding, Work Item characteristic, hypothesis, or conclusion.

## Scope and database set

The frozen primary database set is exactly the six protocol databases: Scopus, Web of Science Core Collection, IEEE Xplore, ACM Digital Library, ScienceDirect, and Springer Nature Link. arXiv, OpenAlex, Crossref, and Google Scholar retain their protocol-defined discovery, metadata, or snowballing roles and are not replacements for these databases.

Database adaptations preserve each canonical branch. Differences in fields, syntax, granularity, and expected noise are operational differences, not changes to the phenomenon being searched.

| Database | Frozen operational strategy |
|---|---|
| Scopus | Exact Boolean strings use `TITLE-ABS-KEY(...)`. No proximity operator is used because the calibrated queries do not require adjacency. |
| Web of Science Core Collection | Exact Boolean strings use `TS=(...)`, whose Topic coverage is not treated as equivalent to Scopus. |
| IEEE Xplore | Advanced Search field clauses use the validated metadata fields `Document Title`, `Abstract`, and `Author Keywords`. Each clause is below the observed 25-term limit. |
| ACM Digital Library | Basic Edition advanced-search clauses use the validated fields `Title`, `Abstract`, and `Author Keyword`, exact phrases, Boolean operators, and wildcards only where shown. |
| ScienceDirect | The query is applied to the validated combined field `Title, abstract or author-specified keywords`. Independent Scopus-style title/abstract/keyword control is not claimed. |
| Springer Nature Link | The default uses the validated `Keywords` control, which searches title, abstract, and body text and is therefore broader than Scopus Topic. Title-only is used only for exact-lineage/benchmark checks. |

**Correction date:** 2026-08-21
**Trigger:** Failed real execution of `S1-F1-IEEE-01-v1`; the displayed `No results found` state was not recorded as a systematic result count.
**Affected database:** IEEE Xplore only

### Correction rationale

The original IEEE representation repeated the complete canonical Boolean expression independently in the Document Title, Abstract, and Author Keywords Advanced Search rows and joined those rows with `OR`. The failed execution demonstrated that the current interface transforms that structure into an internally field-expanded expression that is not a safe executable representation of the frozen query.

The intended semantics are the **union-of-fields interpretation**:

```text
(A in Document Title OR A in Abstract OR A in Author Keywords)
AND
(B in Document Title OR B in Abstract OR B in Author Keywords)
```

This is not the same as requiring every canonical block to occur entirely within one metadata field. The corrected representation therefore scopes every atomic term explicitly to each of the three frozen metadata fields and preserves the canonical Boolean blocks. The correction restores the already-frozen conceptual intent; it does not add, remove, or recalibrate terminology.

### Authoritative IEEE syntax basis

The corrected interface is **IEEE Xplore Command Search**. IEEE's official help documents field-scoped syntax in the form `"field name":value`, exact phrases as `"field name":"exact phrase"`, uppercase `AND`, `OR`, `NOT`, `NEAR`, and `ONEAR`, and a maximum of 25 search terms per search clause. IEEE also states that words within phrases count separately. The documentation does not explicitly resolve whether a field-scoped phrase is counted as a single clause or by its constituent phrase words; this is recorded as a term-count interpretation limitation, not resolved by live testing. The official help pages used for this representation audit are:

- [IEEE Xplore Command Search](https://ieeexplore.ieee.org/Xplorehelp/searching-ieee-xplore/command-search)
- [IEEE Xplore Search Tips](https://ieeexplore.ieee.org/Xplorehelp/searching-ieee-xplore/search-tips)

The repository's database validation independently records the same current field names and 25-term clause limit. The corrected strings do not use unvalidated proximity syntax, nested Boolean expressions after one field name, All Metadata, Full Text, or IEEE Terms.

The union is performed only after each piece has been executed and its raw output preserved. No deduplication occurs during execution or export; a record returned by multiple pieces retains every Query ID origin until the later deduplication phase.

Each split piece receives its own execution provenance and later records separately:

- database-reported count for that Query ID;
- raw captured count for that Query ID;
- exact literal expression and selected fields;
- raw artifact and execution status.

Piece counts must not be summed as a unique branch count. Overlap is expected; a unique branch count belongs after later raw-record reconciliation and deduplication.
